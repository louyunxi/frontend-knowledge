# 工程化与质量保障（Husky + ESLint + Commitlint + CI）

> 适用场景：基于 Vue3 + Vite 的**纯 H5** 项目，需要在团队协作中保证代码质量与部署自动化。
> 本文档提炼 vue3-h5-template 的工程化体系。


## 二、Husky Git Hooks

### 2.1 安装

```json
// package.json
"scripts": {
  "prepare": "husky install"
}
```

`pnpm install` 时自动执行 `prepare`，安装 Husky。

### 2.2 Hooks 文件

```
.husky/
├── commit-msg              # 校验 commit 信息
└── lintstagedrc.js         # lint-staged 配置
```

### 2.3 commit-msg hook

```bash
# .husky/commit-msg
npx --no -- commitlint --edit "$1"
```

每次 `git commit` 时，commitlint 校验 commit 信息格式。

### 2.4 lint-staged（暂存区文件修复）

```js
// .husky/lintstagedrc.js
module.exports = {
  '*.{js,jsx,ts,tsx,vue,json,md}': ['eslint --fix'],
  '*.{css,scss,postcss,less}': ['stylelint --fix'],
}
```

`git commit` 时只对**暂存区文件**（git add 过的文件）执行 lint --fix。

## 三、ESLint（Flat Config）

### 3.1 配置（极简）

```js
// eslint.config.js
import antfu from '@antfu/eslint-config'

export default antfu()
```

仅一行，继承 Anthony Fu 的 ESLint 预设（含 Vue/TS/格式化规则）。

### 3.2 常用命令

```bash
pnpm lint         # 检查全部
pnpm lint:fix     # 自动修复
```

### 3.3 配套 stylelint

```json
// package.json (推荐补充，未在原项目)
"devDependencies": {
  "stylelint": "^16.x",
  "stylelint-config-standard": "^36.x"
}
```

`.lintstagedrc.js` 已包含 stylelint 调用，建议补充 `stylelint.config.js`：

```js
// stylelint.config.js
export default {
  extends: ['stylelint-config-standard'],
  rules: {
    'selector-class-pattern': null,  // 允许 Tailwind 任意命名
    'no-descending-specificity': null,
  },
}
```

## 四、Commitlint（提交信息规范）

### 4.1 配置

```js
// commitlint.config.js
export default {
  ignores: [commit => commit.includes('init')],
  extends: ['@commitlint/config-conventional'],
  rules: {
    'body-leading-blank': [2, 'always'],
    'footer-leading-blank': [1, 'always'],
    'header-max-length': [2, 'always', 108],
    'subject-empty': [2, 'never'],
    'type-empty': [2, 'never'],
    'type-enum': [
      2,
      'always',
      [
        'feat', 'fix', 'perf', 'style', 'docs', 'test',
        'refactor', 'build', 'ci', 'chore', 'revert',
        'wip', 'workflow', 'types', 'release',
      ],
    ],
  },
}
```

### 4.2 15 种 type 类型

| type | 含义 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat(login): 增加手机号登录` |
| `fix` | 修复 Bug | `fix: 修复登录页白屏` |
| `perf` | 性能优化 | `perf(list): 虚拟列表优化` |
| `style` | 代码格式（无功能变化） | `style: 格式化 src/api/` |
| `docs` | 文档 | `docs: 更新 README` |
| `test` | 测试 | `test: 增加单元测试` |
| `refactor` | 重构（非新功能、非 Bug） | `refactor(store): 拆分 Pinia 模块` |
| `build` | 构建系统/依赖 | `build: 升级 vite 到 8` |
| `ci` | CI 配置 | `ci: 增加 lint-staged` |
| `chore` | 其他杂项 | `chore: 更新 .gitignore` |
| `revert` | 撤销 | `revert: 撤销 abc123` |
| `wip` | 开发中 | `wip: 临时提交` |
| `workflow` | 工作流 | `workflow: 改造发布流程` |
| `types` | 类型定义 | `types: 补充 User 类型` |
| `release` | 发布 | `release: v1.0.0` |

### 4.3 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

示例：

```
feat(user): 增加用户头像上传功能

支持 jpg/png 格式，最大 2MB
上传成功后自动裁剪为 200x200

Closes #123
```

## 五、standard-version（自动版本管理）

### 5.1 命令

```bash
pnpm release
```

自动完成：
1. 根据 commit 类型自动升级版本号（feat → minor, fix → patch, BREAKING CHANGE → major）
2. 生成 CHANGELOG.md
3. 创建 git tag
4. 提交变更

### 5.2 配置（默认即可）

```json
// .versionrc.json
{
  "types": [
    { "type": "feat", "section": "Features" },
    { "type": "fix", "section": "Bug Fixes" },
    { "type": "perf", "section": "Performance Improvements" },
    { "type": "revert", "section": "Reverts" },
    { "type": "docs", "section": "Documentation", "hidden": false },
    { "type": "style", "section": "Styles", "hidden": true },
    { "type": "chore", "section": "Miscellaneous Chores", "hidden": true },
    { "type": "test", "section": "Tests", "hidden": true },
    { "type": "build", "section": "Build System", "hidden": true },
    { "type": "ci", "section": "Continuous Integration", "hidden": true },
    { "type": "refactor", "section": "Code Refactoring", "hidden": true }
  ]
}
```

## 六、CI/CD（GitHub Actions）

### 6.1 工作流

```yaml
# .github/workflows/main.yml
name: Build and Deploy
permissions:
  contents: write
on:
  push:
    branches:
      - master
jobs:
  deploy:
    concurrency: ci-${{ github.ref }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout 🛎️
        uses: actions/checkout@v4

      - name: Setup node
        uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: https://registry.npmjs.com/

      - name: Setup pnpm
        uses: pnpm/action-setup@v3
        with:
          version: 9
          run_install: false

      - name: Deploy 🔧
        run: |
          pnpm install --no-frozen-lockfile
          sed -i "s#VITE_PUBLIC_PATH = \"/\"#VITE_PUBLIC_PATH = /vue3-h5-template/#g" $(pwd)/.env.production
          pnpm build

      - name: Deploy 🚀
        uses: JamesIves/github-pages-deploy-action@v4
        with:
          branch: gh-pages
          folder: dist
          clean: true
```

### 6.2 关键点

| 步骤 | 作用 |
|---|---|
| `actions/checkout@v4` | 拉取代码 |
| `actions/setup-node@v4` | 安装 Node 20 |
| `pnpm/action-setup@v3` | 安装 pnpm 9 |
| `pnpm install --no-frozen-lockfile` | 安装依赖（允许 lockfile 不匹配） |
| `sed -i ...` | 替换生产环境 base 路径为 GitHub Pages 子路径 |
| `pnpm build` | 构建（自动运行 type-check） |
| `JamesIves/github-pages-deploy-action@v4` | 部署 dist 到 gh-pages 分支 |

### 6.3 部署到其他平台

| 平台 | 调整点 |
|---|---|
| Vercel | 直接连接 GitHub 仓库，零配置 |
| Netlify | 同上，自带 `pnpm build` |
| Nginx 自建 | 在 CI 末尾加 scp/rsync 上传 |
| 阿里云 OSS | 用 `ossutil` 上传 dist 目录 |

## 七、TypeScript 严格模式

```json
// tsconfig.json
{
  "compilerOptions": {
    "strict": true,                  // 启用所有严格选项
    "strictFunctionTypes": true,     // 函数类型严格
    "noImplicitAny": true,           // 隐式 any 报错
    "strictNullChecks": true,        // null/undefined 严格区分
    "noUnusedLocals": true,          // 未使用变量报错
    "skipLibCheck": true             // 跳过 .d.ts 检查（加快编译）
  }
}
```

### build 流程

```bash
pnpm build
  ↓
run-s build-only type-check
  ↓
  ├─ vite build  (构建产物)
  └─ vue-tsc --noEmit  (类型检查)
```

并行检查保证：**产物可用 + 类型正确**。

## 八、常见踩坑

1. **`pnpm install` 卡在 prepare**：Husky 9 行为变化，可能要手动 `pnpm dlx husky init`。
2. **commitlint 不生效**：检查 `.husky/commit-msg` 文件是否包含 `npx --no -- commitlint --edit "$1"`。
3. **lint-staged 失败**：`eslint --fix` 可能因配置文件报错，建议加 `--max-warnings 0`。
4. **GitHub Pages 部署路径错误**：必须把 `VITE_PUBLIC_PATH` 改为 `/repo-name/`。
5. **`pnpm install --no-frozen-lockfile`** 会忽略 lockfile，可能引入不一致，建议只在 CI 用。
6. **standard-version 中文 commit 不规范**：提交信息必须英文，CHANGELOG 才能正确生成。
7. **Vue3.5 `useId()` 在 ESLint 报错**：需要 `@antfu/eslint-config` v3+。
