# 网络层与样式方案（Axios + Mock + Tailwind v4 + vmin）

> 适用场景：基于 Vue3 + Vite 的**纯 H5** 移动端项目。
> 本文档提炼 vue3-h5-template 的网络请求、Mock 数据、CSS 方案三大基础设施。

## 一、网络层（Axios 封装）

### 1.1 入口

```ts
// src/utils/http/index.ts
import Axios from 'axios'
import { showFailToast } from 'vant'
import { ContentTypeEnum, ResultEnum } from '@/enums/request-enum'
import NProgress from '../progress'
import 'vant/es/toast/style'

const configDefault: AxiosRequestConfig = {
  headers: { 'Content-Type': ContentTypeEnum.JSON },
  timeout: 0,
  baseURL: import.meta.env.VITE_BASE_API,
  data: {},
}

const axiosInstance: AxiosInstance = Axios.create(configDefault)

axiosInstance.interceptors.request.use(
  (config) => { NProgress.start(); return config },
  (error) => { showFailToast(error.message); return Promise.reject(error) },
)

axiosInstance.interceptors.response.use(
  (response) => {
    NProgress.done()
    const { code, result } = response.data
    const isSuccess = result && Reflect.has(response.data, 'code') && code === ResultEnum.SUCCESS
    return isSuccess ? result : Promise.reject(response.data)
  },
  (error) => {
    NProgress.done()
    if (Axios.isCancel(error)) return Promise.reject(error)
    const status = error.response?.status
    const message = (status && HTTP_ERROR_MAP[status]) || '网络连接故障'
    showFailToast(message)
    return Promise.reject(error)
  },
)

export const http = { get, post, put, delete, request, requestWithCancel }
```

### 1.2 三大设计要点

#### ① 统一 `http` 对象暴露 5 个方法 + 1 个可取消请求

```ts
http.get<T>(url, config?)
http.post<T>(url, data?, config?)
http.put<T>(url, data?, config?)
http.delete<T>(url, config?)
http.request<T>(config)

// 可取消请求 — 页面卸载时取消未完成请求
http.requestWithCancel(config) // → { promise, cancel }
```

**可取消请求使用场景**：

```vue
<script setup lang="ts">
const { promise, cancel } = http.requestWithCancel({ url: '/api/data' })
onBeforeUnmount(() => cancel())
const data = await promise
</script>
```

底层使用 `AbortController`，完全替代旧的 `CancelToken`。

#### ② HTTP 状态码 → 错误消息映射

```ts
const HTTP_ERROR_MAP: Record<number, string> = {
  400: '请求错误',
  401: '未授权，请登录',
  403: '拒绝访问',
  404: '请求地址出错',
  408: '请求超时',
  500: '服务器内部错误',
  // ...
}
```

#### ③ 业务返回 code 统一拦截

```ts
const { code, result } = response.data
const isSuccess = result && Reflect.has(response.data, 'code') && code === ResultEnum.SUCCESS
```

后端约定返回结构：

```json
{
  "code": 0,        // 0 = 成功
  "message": "OK",
  "result": { ... } // 业务数据
}
```

**成功**：直接返回 `result`（不是 `response.data`），调用方无需再次解包。
**失败**：返回 `Promise.reject(response.data)`，由调用方处理。

### 1.3 业务代码使用示例

```ts
// src/api/mock/index.ts
import { http } from '@/utils/http'

export interface UserItem {
  id: number
  name: string
  avatar: string
  city: string
}

export function getListApi() {
  return http.get<{ list: UserItem[] }>('/list/get')
}

export function submitFormApi(data: { name: string, message: string }) {
  return http.post<{ id: string, createdAt: string }>('/form/submit', data)
}
```

```vue
<!-- views/tools/index.vue -->
<script setup lang="ts">
const userList = ref<UserItem[]>([])

async function handleGetRequest() {
  try {
    const { list } = await getListApi()
    userList.value = list
    showSuccessToast('GET 请求成功')
  }
  catch {
    showFailToast('GET 请求失败')
  }
}
</script>
```

### 1.4 关键枚举

```ts
// src/enums/request-enum.ts
export enum ContentTypeEnum {
  FORM_URLENCODED = 'application/x-www-form-urlencoded;charset=UTF-8',
  FORM_DATA = 'multipart/form-data;charset=UTF-8',
  JSON = 'application/json;charset=UTF-8',
}

export enum ResultEnum {
  SUCCESS = 0,
  ERROR = 1,
}
```

## 二、Mock 数据方案

### 2.1 工具链

- `vite-plugin-mock-dev-server`：dev server 拦截 mock 请求
- `mockjs`：生成假数据

### 2.2 Vite 配置

```ts
// vite.config.ts
import { mockDevServerPlugin } from 'vite-plugin-mock-dev-server'

plugins: [mockDevServerPlugin()]

server: {
  proxy: {
    '^/dev-api': { target: '' },  // 空 target 让 mock 接管
  },
}
```

### 2.3 Mock 文件

```ts
// mock/list.mock.ts
import Mock from 'mockjs'
import { defineMock } from 'vite-plugin-mock-dev-server'

export default defineMock([
  {
    url: '/dev-api/list/get',
    delay: 800,
    body: () => ({
      code: 0,
      message: 'OK',
      result: Mock.mock({
        'list|5': [{
          'id|+1': 1,
          'name': '@cname(true)',
          'avatar': Mock.Random.image('48x48', '#50B347', '#fff', 'User'),
          'city': '@city(true)',
        }],
      }),
    }),
  },
  {
    url: '/dev-api/form/submit',
    method: 'POST',
    delay: 600,
    body: () => ({
      code: 0,
      message: '提交成功',
      result: { id: Mock.Random.guid(), createdAt: Mock.Random.datetime('yyyy-MM-dd HH:mm:ss') },
    }),
  },
])
```

### 2.4 调用链

```
浏览器 → /dev-api/list/get
  ↓
Vite dev server 看到 /dev-api 前缀
  ↓
proxy 配置：target 为空 → 不转发
  ↓
mockDevServerPlugin 接管
  ↓
查找 mock/list.mock.ts 中匹配的 url
  ↓
执行 body() 返回数据
  ↓
浏览器收到 { code: 0, result: { list: [...] } }
```

### 2.5 重要约定

1. **URL 必须以 `/dev-api` 开头**，与 proxy 匹配。
2. **生产环境必须关闭 mock**，避免泄露假数据。
3. **`baseURL: import.meta.env.VITE_BASE_API`** 控制实际请求前缀。

## 三、样式方案（Tailwind v4 + Less + vmin）

### 3.1 全局样式入口

```ts
// src/main.ts
import 'normalize.css/normalize.css'  // 浏览器样式重置
import './styles/index.less'           // 全局 less（字体、动画）
import './styles/tailwind.css'         // Tailwind v4 入口
import 'virtual:svg-icons/register'   // SVG 雪碧图注册
```

### 3.2 Tailwind v4 配置

```css
/* src/styles/tailwind.css */
@import "tailwindcss";

/* class 模式深色主题（与 v3 的 darkMode: 'class' 等效） */
@variant dark (&:is(.dark *));
```

**与 v3 关键差异**：
- 无需 `tailwind.config.js`。
- 配置全部用 CSS 语法 + `@theme` 指令。
- `@variant dark (...)` 是 v4 自定义 dark 模式的方式。

### 3.3 PostCSS 链

```js
// postcss.config.js
export default {
  plugins: {
    '@tailwindcss/postcss': {},
    'postcss-rem-to-pixel': { rootValue: 16, propList: ['*'] },
    'cnjm-postcss-px-to-viewport': {
      viewportWidth: 375,
      unitPrecision: 2,
      viewportUnit: 'vmin',
      fontViewportUnit: 'vmin',
      unitToConvert: 'px',
      mediaQuery: true,
    },
  },
}
```

**3 个插件职责**：

| 顺序 | 插件 | 作用 |
|---|---|---|
| 1 | `@tailwindcss/postcss` | Tailwind v4 编译 |
| 2 | `postcss-rem-to-pixel` | Tailwind 输出的 rem 转回 px |
| 3 | `cnjm-postcss-px-to-viewport` | px 转 vmin |

### 3.4 CSS 变量（亮色 / 暗色）

```less
/* src/styles/variables.less */
:root {
  --color-text: var(--van-text-color, #323233);
  --color-background-2: #fafafa;
  --color-block-background: #ffffff;
  --color-border: var(--van-border-color, #ebedf0);
}

html.dark {
  --color-text: var(--van-text-color, #f5f5f5);
  --color-background-2: var(--van-background-2, #1c1c1e);
  --color-block-background: var(--van-border-color, #3a3a3c);
  --color-border: var(--van-border-color, #3a3a3c);
}
```

要点：
- **业务变量引用 Vant 变量**，确保主题切换时联动。
- **`var(--van-text-color, #323233)`** 兜底，未加载 Vant 样式时也有默认值。

## 四、CSS 工具合并

```ts
// src/utils/class-names.ts
import { clsx } from 'clsx'
import { twMerge } from 'tailwind-merge'

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

使用场景：

```vue
<script setup lang="ts">
import { cn } from '@/utils/class-names'

const isActive = ref(false)
</script>

<template>
  <div :class="cn('p-4 rounded', isActive && 'bg-blue-500')">
    内容
  </div>
</template>
```

`twMerge` 会智能去重冲突的 Tailwind 类（如 `p-2 p-4` 只保留 `p-4`）。

## 五、关键决策对比

| 维度 | 选择 | 替代 | 理由 |
|---|---|---|---|
| HTTP 客户端 | Axios 1 | Fetch | 拦截器成熟，TS 类型好 |
| 取消请求 | AbortController | CancelToken（旧） | 浏览器原生，未来标准 |
| Mock | vite-plugin-mock-dev-server | mockjs 单独用 | 集成度最高 |
| 数据生成 | mockjs | faker.js | 中文名/城市支持更好 |
| 样式方案 | Tailwind v4 + Less | 纯 SCSS / 纯 Tailwind | 原子化 + 灵活定制 |
| 视口单位 | vmin | vw / rem | 横竖屏一致性 |
| 适配策略 | postcss px→vmin | flexible.js 动态算 rem | 静态方案，构建期完成 |
| 类名合并 | clsx + tailwind-merge | classnames | 解决 Tailwind 类冲突 |

## 六、常见踩坑

1. **baseURL 配置错误**：开发用 `/dev-api`，生产必须改为真实域名。
2. **Mock 拦截失效**：检查 `vite.config.ts` 的 `server.proxy['^/dev-api'].target` 是否为空字符串。
3. **Toast 样式丢失**：函数式 API 必须 `import 'vant/es/toast/style'`。
4. **请求未携带 Cookie**：默认 axios 不携带，需要设置 `withCredentials: true`。
5. **CSS 变量穿透作用域**：scoped 样式无法访问父级变量，需用 `:deep` 或全局。
6. **postcss-rem-to-pixel 报错**：Tailwind v4 必须安装 `@tailwindcss/postcss` 而不是旧版。
7. **vmin 在 Safari iOS 有兼容性问题**：极少部分旧版 iOS 需 `vm` 兼容。
