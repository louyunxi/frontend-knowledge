# 动效设计原则

## 概述

动效是现代 Web 设计的重要组成部分，但需要克制和有目的地使用。

好的动效可以：
- 提供视觉反馈
- 建立空间关系
- 引导用户注意力
- 增加产品个性

但过度使用动效会：
- 分散注意力
- 影响性能
- 显得廉价和模板化

---

## 动效类型

### 1. 入场动画 (Entrance Animation)

```
定义：元素首次出现在页面时

适用场景：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 合适：
- Hero 区域的首次展示
- 关键内容块的加载
- 页面切换后的新内容

❌ 过度：
- 每个 section 都 fade-in
- 列表每个 item 都 stagger
- 页面滚动每个元素都动

最佳实践：
- 选择 1-2 个关键区域使用
- 保持动画简洁
- 避免延迟过多
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 2. 用户触发动画 (User-triggered Animation)

```
定义：用户操作触发的动画

适用场景：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 强烈推荐：
- 按钮点击反馈
- 表单提交成功
- 展开/折叠内容
- Modal/Drawer 弹出
- 拖拽排序
- 文件上传进度

❌ 不推荐：
- 鼠标 hover 每个卡片
- 每个链接悬停
- 焦点 focus 每个输入框

关键原则：
用户操作 → 即时反馈 → 显示变化

示例：
点击按钮 → 按钮下沉 + 颜色变化 → 显示成功状态
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 3. 滚动驱动动画 (Scroll-driven Animation)

```
定义：滚动页面时触发的动画

适用场景：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 合适：
- 数据可视化展示
- 叙事性滚动
- 视差效果
- 滚动指示

❌ 谨慎：
- 每个元素都随滚动移动
- 过于复杂的视差
- 性能密集型动画

性能考虑：
- 使用 transform 和 opacity
- 避免触发布局属性的动画
- 考虑 reduced-motion 用户
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 4. 过渡动画 (Transition Animation)

```
定义：状态或视图切换时的动画

适用场景：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 合适：
- 页面路由切换
- Tab 切换
- Modal/Drawer 打开关闭
- 侧边栏展开折叠
- 设置面板切换

时间控制：
- 快速切换：150-250ms
- 页面过渡：250-400ms
- 复杂动画：400-600ms

缓动函数：
- 进入：ease-out (快速开始，慢速结束)
- 退出：ease-in (慢速开始，快速结束)
- 复杂：自定义 cubic-bezier
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 克制使用原则

### 1. 单点记忆原则

```
💡 核心原则：
让一个元素成为记忆点，其他保持克制

❌ 错误示例：
- 页面加载：每个 section 都 fade-in
- 卡片悬停：每个卡片都 scale
- 按钮点击：每个按钮都有 bounce
- 页面切换：每个页面都有复杂过渡

✅ 正确示例：
- Hero 区域：复杂的入场动画
- 其他区域：简单或无动画
- 交互反馈：即时但简洁
- 页面过渡：单一一致的模式

结果：
一个记忆点 > 多个平庸的动效
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 2. 功能优先原则

```
动效应该服务于功能，不是装饰

❌ 装饰性动效：
- 背景装饰动画
- Logo 持续旋转
- 飘落的花瓣效果
- 鼠标跟随光效

✅ 功能性动效：
- 显示状态变化（加载、成功、失败）
- 提供反馈（点击、拖拽）
- 建立空间关系（Modal 弹出位置）
- 引导注意力（新内容、通知）

测试问题：
"这个动效删掉后，用户会困惑吗？"
- 会 → 保留
- 不会 → 删除
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 3. 性能优先原则

```
性能差的动效 = 差的用户体验

✅ 性能友好的属性：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
- transform: translate()
- transform: scale()
- transform: rotate()
- opacity

❌ 避免的属性：
- width, height
- margin, padding
- left, top, right, bottom
- font-size

✅ 最佳实践：
- 使用 will-change 提示浏览器
- 避免同时动画太多元素
- 考虑 reduced-motion 媒体查询
- 测试移动端性能
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 动画时长指南

### 基于动画类型

```
快速交互反馈：
- Hover: 100-150ms
- Click: 100-200ms
- Toggle: 150-250ms

内容切换：
- Tab 切换: 200-300ms
- Modal 打开: 250-350ms
- Drawer 滑出: 250-350ms
- Dropdown: 150-250ms

页面过渡：
- 简单淡入: 200-300ms
- 滑动过渡: 250-400ms
- 复杂 choreography: 400-600ms

Orchestrated（编排）：
- 列表 stagger: 50-100ms 每个
- 总时长: 300-800ms

❌ 避免：
- 超过 1000ms 的单个动画
- 超过 2000ms 的总编排时长
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## Reduced Motion 支持

### 实现方式

```css
/* 默认动画 */
.animated-element {
  transition: transform 0.3s ease-out;
}

/* 减少动效偏好 */
@media (prefers-reduced-motion: reduce) {
  .animated-element {
    transition: opacity 0.15s ease-out;
  }
}

/* 或者完全禁用 */
@media (prefers-reduced-motion: reduce) {
  .animated-element {
    transition: none;
  }
}
```

```javascript
// JavaScript 中检测
const prefersReducedMotion = window.matchMedia(
  '(prefers-reduced-motion: reduce)'
).matches;

if (prefersReducedMotion) {
  // 使用简化动画或静态
}
```

## 动效检查清单

```
设计前：
□ 这个动效的目的是什么？
□ 删除它会影响用户体验吗？
□ 是否性能友好？
□ 是否考虑了 reduced-motion？

设计中：
□ 是否过于分散？
□ 是否有清晰的焦点？
□ 时长是否合适？
□ 是否与其他交互一致？

完成后：
□ 动效是否服务于功能？
□ 是否有记忆点？
□ 是否测试了移动端性能？
□ 是否支持 accessibility？
```
