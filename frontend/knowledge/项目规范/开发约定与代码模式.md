# 开发约定与代码模式（vue3-h5-template）

> 适用场景：基于 Vue3 + Vite 的**纯 H5** 移动端项目。
> 本文档提炼 vue3-h5-template 的开发约定、命名规范与常见代码模式。

## 一、组件编写模式

### 1.1 标准 `<script setup>` + `defineOptions`

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'
import NavBar from '@/components/nav-bar/index.vue'

defineOptions({
  name: 'About',  // 必须与路由 name 完全一致
})

const count = ref(0)
const double = computed(() => count.value * 2)
</script>

<template>
  <div>{{ double }}</div>
</template>
```

要点：
- **Vue 3.3+ 才有的 `defineOptions` 宏**，无需额外 export。
- 使用 `lang="ts"` 启用 TS 类型检查。
- 不要写 `export default {}`。

### 1.2 组件命名规则

| 场景 | 命名 | 文件 |
|---|---|---|
| 多单词组件 | `NavBar` | `nav-bar/index.vue` |
| 单单词组件 | `Grid` | `grid/index.vue` |
| 包装组件 | `IIcon` | `i-icon/index.vue` |
| 业务组件 | `UserCard` | `user-card/index.vue` |

### 1.3 props 模式

```vue
<script setup lang="ts">
interface Props {
  name: string
  count?: number
  className?: string
}

const props = withDefaults(defineProps<Props>(), {
  count: 0,
  className: '',
})
</script>
```

或使用 `defineProps<T>()` + 类型标注：

```vue
<script setup lang="ts">
const props = defineProps<{
  name: string
  count?: number
}>()
</script>
```

### 1.4 emits 模式

```vue
<script setup lang="ts">
const emit = defineEmits<{
  (e: 'change', value: string): void
  (e: 'update', id: number): void
}>()

function handleChange(value: string) {
  emit('change', value)
}
</script>
```

## 二、Pinia Store 模式（Setup Store）

### 2.1 完整示例

```ts
// src/store/modules/user.ts
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', () => {
  // state
  const token = ref<string>('')
  const userInfo = ref<UserInfo | null>(null)

  // getters
  const isLoggedIn = computed(() => !!token.value)
  const userName = computed(() => userInfo.value?.name ?? '游客')

  // actions
  function setToken(t: string) {
    token.value = t
  }

  function setUserInfo(info: UserInfo) {
    userInfo.value = info
  }

  function logout() {
    token.value = ''
    userInfo.value = null
  }

  return { token, userInfo, isLoggedIn, userName, setToken, setUserInfo, logout }
})
```

### 2.2 在组件中使用

```vue
<script setup lang="ts">
import { storeToRefs } from 'pinia'

const userStore = useUserStore()

// 解构响应式状态（必须用 storeToRefs）
const { isLoggedIn, userName } = storeToRefs(userStore)

// 方法可以直接解构（不需要 storeToRefs）
const { logout } = userStore
</script>
```

### 2.3 跨 store 调用

```ts
// 在路由守卫中
router.beforeEach((to, _from, next) => {
  useCachedViewStore().addCachedView(to)
  next()
})
```

### 4.2 错误处理统一在拦截器

```ts
// http/index.ts 拦截器
axiosInstance.interceptors.response.use(
  (response) => {
    const { code, result } = response.data
    if (code === ResultEnum.SUCCESS) return result  // 直接返回业务数据
    return Promise.reject(response.data)             // 业务错误
  },
  (error) => {
    showFailToast(error.message)                     // 统一 toast
    return Promise.reject(error)
  },
)
```

组件内只需 `try/catch` 处理业务错误。

## 五、样式模式

### 5.1 Tailwind v4 原子类（首选）

```vue
<template>
  <div class="px-[12px] py-[8px] text-[14px] bg-[var(--color-block-background)] rounded-[12px]">
    内容
  </div>
</template>
```

要点：
- **`[]` 表示任意值**（如 `text-[14px]`）。
- **`text-[var(--xxx)]`** 引用 CSS 变量。
- **响应式前缀**：`md:text-[18px]`、`dark:bg-[#fff]`。

### 5.2 Tailwind 与 Less 混用

```vue
<template>
  <div class="card">
    <h3 class="title">标题</h3>
  </div>
</template>

<style lang="less" scoped>
@import "@/styles/mixin.less";

.card {
  .clearfix();
  padding: 12px;
  border-radius: 12px;

  .title {
    font-size: 18px;
    font-weight: bold;
  }
}
</style>
```

原则：
- **布局/间距/颜色 → Tailwind**（小颗粒度调整）。
- **复杂组合/动画/特殊效果 → scoped less**（大颗粒度封装）。

### 5.3 CSS 变量驱动主题

```vue
<template>
  <div class="text-[var(--color-text)] bg-[var(--color-block-background)]">
    内容
  </div>
</template>
```

主题切换时颜色自动跟随。

## 十、关键决策对比

| 决策 | 选择 | 理由 |
|---|---|---|
| 组件写法 | `<script setup>` + `defineOptions` | Vue 3.3+ 标准 |
| Store 写法 | Setup Store | TS 推断友好 |
| 路由模式 | Hash | 静态部署友好 |
| 样式方案 | Tailwind v4 + Less | 原子化 + 灵活 |
| 类型导入 | `import type` | 强制隔离 |
| 文件夹命名 | kebab-case | 与 Vite/TS 解析一致 |

## 十一、常见踩坑

1. **`<script setup>` 中 `defineOptions` 报错**：Vue 版本需 ≥ 3.3。
2. **storeToRefs 忘记用**：解构后丢失响应性。
3. **路由 name 与组件 name 不一致**：keep-alive 不生效。
4. **CSS 变量在 scoped 中无法覆盖**：用 `:deep()` 或全局样式。
5. **`@apply` 在 Tailwind v4 不工作**：v4 用 `@theme` 替代。
6. **Pinia 自动解构丢失响应性**：必须 `storeToRefs`。
7. **Vant 函数式组件样式缺失**：手动 `import 'vant/es/<name>/style'`。
