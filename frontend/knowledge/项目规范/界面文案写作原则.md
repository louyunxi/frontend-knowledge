# 界面文案写作原则

## 概述

界面中的文字是设计内容，不是装饰。它们的存在只有一个原因：让产品更容易理解和使用。

本知识提供 UI 文案写作的最佳实践，帮助你写出清晰、一致、有帮助的界面文字。

---

## 核心原则

### 1. 用户视角

```
❌ 系统视角：
- "Webhook 配置"
- "数据库同步失败"
- "错误码: E_2001"

✅ 用户视角：
- "管理通知设置"
- "同步未完成，请重试"
- "保存失败，请检查网络"

原则：
用用户能理解的语言，而不是系统如何构建的语言。

用户管理通知，不是配置 webhook。
用户订阅更新，不是设置 webhook。
```

### 2. 主动语态

```
❌ 被动语态：
- "变更已保存"
- "文件已被上传"
- "错误已被检测到"

✅ 主动语态：
- "保存成功"
- "上传完成"
- "检测到错误"

原因：
主动语态更直接、更清晰、更有力量。
```

### 3. 精确命名

```
❌ 模糊命名：
- "确定"
- "处理中"
- "完成"

✅ 精确命名：
- "保存更改"
- "正在保存..."
- "已保存"

CTA 按钮命名：
- "Save changes" ✓
- "Submit" ✗
- "Publish" ✓
- "Send" ✗

原则：
CTA 应该准确描述点击后会发生什么。
```

### 4. 词汇一致性

```
❌ 不一致：
- 按钮: "发布"
- Toast: "已发布"
- 错误: "发布失败"
- 弹窗: "发布成功"

✅ 一致：
- 按钮: "发布"
- Toast: "已发布"
- 错误: "发布失败"
- 弹窗: "已发布"

原则：
同一个操作在整个流程中使用相同的名称。
按钮说什么，Toast 就说什么。
```

## 错误提示

### 错误提示原则

```
1. 说明发生了什么
━━━━━━━━━━━━━━━━━━━━━━━━━━━
❌ 模糊：
"出错了"
"操作失败"
"系统错误"

✅ 精确：
"无法保存，因为文件名包含非法字符"
"网络连接失败，请检查网络设置"
"此邮箱已被注册"
━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. 说明如何解决
━━━━━━━━━━━━━━━━━━━━━━━━━━━
❌ 只说错误：
"保存失败"

✅ 给出解决方案：
"保存失败，文件大小超出限制（最大 10MB）"
"无法连接服务器，请检查网络后重试"
━━━━━━━━━━━━━━━━━━━━━━━━━━━

3. 使用界面语气
━━━━━━━━━━━━━━━━━━━━━━━━━━━
❌ 人称语气：
"很抱歉给您带来不便"
"请您稍后重试"
"请您检查输入"

✅ 界面语气：
"无法保存，请检查网络设置"
"请使用有效的邮箱地址"
"文件过大，请压缩后重试"
━━━━━━━━━━━━━━━━━━━━━━━━━━━

4. 永不道歉
━━━━━━━━━━━━━━━━━━━━━━━━━━━
❌ 不要：
"抱歉出错了"
"对不起，操作失败"
"很抱歉通知您..."

✅ 要：
"出错了"
"操作失败"
"无法完成"
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 空状态

### 空状态设计原则

```
空状态 = 行动的邀请，不是空白

1. 解释为什么是空的
━━━━━━━━━━━━━━━━━━━━━━━━━━━
好：
"暂无通知"
"还没有订单"
"收藏列表为空"

更好：
"暂无通知"
↓
"你还没有收到任何通知"
"还没有订单"
↓
"这里会显示你的订单"
"收藏为空"
↓
"收藏你喜欢的商品"
━━━━━━━━━━━━━━━━━━━━━━━━━━━

2. 提供行动指引
━━━━━━━━━━━━━━━━━━━━━━━━━━━
好：
"暂无数据"

更好：
"暂无数据
[创建第一个项目]"

好：
"没有通知"

更好：
"没有新通知
有新动态时会在这里显示
[查看全部通知]"
━━━━━━━━━━━━━━━━━━━━━━━━━━━

3. 保持友好语气
━━━━━━━━━━━━━━━━━━━━━━━━━━━
好：
"错误：没有数据"

更好：
"还没有内容
开始添加一些内容吧
[添加内容]"
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 标签和元数据

### 避免模板化标签

```
❌ 模板化标签：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
- "LOCATION: New York"
  地点: 纽约

- "PRICE · $99"
  价格 · $99

- "Category — Electronics"
  分类 — 电子产品

✅ 更好的方式：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
- "New York"
  纽约

- "$99"
  $99

- "Electronics"
  电子产品

原则：
- 删除不必要的标签
- 直接显示内容
- 如果必须用标签，保持简洁
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 标签格式

```
❌ 不要：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
- ALL CAPS（显得廉价）
  LABEL: content

- 冒号分隔（显得老套）
  标签: 内容

- 长破折号（视觉噪音）
  Label — Description

✅ 更好的方式：
━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Sentence case 或 Title Case
  Label / Content

- 使用视觉层次代替文字标签
  大标题 = 主信息
  小字 = 次要信息

- 如果必须用分隔符，用空格
  Label  Content
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 语气指南

### 语气类型

```
正式商务：
- "提交申请"
- "处理中"
- "已拒绝"

友好直接：
- "提交"
- "处理中"
- "不符合条件"

技术文档：
- "保存到服务器"
- "请求超时"
- "权限不足"

选择原则：
根据产品类型和目标受众选择语气。
B2B 产品可能更正式。
面向消费者的产品可以更友好。
```

### 简洁原则

```
❌ 啰嗦：
"请注意，您提交的内容将经过审核，审核通过后即可发布。"

✅ 简洁：
"提交后需审核，审核通过自动发布"

❌ 啰嗦：
"如果您忘记了密码，请点击下方的'忘记密码'链接，通过验证后将收到重置密码的邮件。"

✅ 简洁：
"忘记密码？[重置密码]"
```

## 检查清单

```
写作前：
□ 这个文字的目的是什么？
□ 用户能理解这个术语吗？
□ 是否使用了主动语态？
□ 词汇是否一致？

错误提示：
□ 是否说明了发生了什么？
□ 是否说明了如何解决？
□ 是否没有道歉？
□ 是否使用了界面语气？

空状态：
□ 是否解释了为什么是空的？
□ 是否提供了行动指引？
□ 是否保持友好语气？

标签：
□ 是否删除了不必要的标签？
□ 是否使用了合适的格式？
□ 是否避免了全大写？
```
