> 适用场景：基于 Vue3 + Vite 构建的**纯 H5** 移动端项目。
> 本文档以 yulimchen/vue3-h5-template 为准，是该项目根目录到 src/ 的完整结构拆解。

## 三、目录命名约定

| 目录 | 命名规范 | 作用 |
|---|---|---|
| `src/api/` | 业务模块文件夹 | 按业务域拆分（如 `user/`、`order/`） |
| `src/components/` | PascalCase | 通用业务组件，自动按需导入 |
| `src/enums/` | 单词 | 全局枚举 |
| `src/icons/svg/` | kebab-case | 本地 SVG 图标源文件 |
| `src/layout/` | 单文件 | 全局布局 |
| `src/router/` | 模块文件 | 路由 |
| `src/store/modules/` | kebab-case | Pinia 子模块 |
| `src/styles/` | 全局 | 样式 |
| `src/typings/` | `*.d.ts` | TypeScript 类型 |
| `src/utils/` | 单词 | 工具 |
| `src/views/<name>/` | 每个页面一个文件夹 | 页面（包含 `index.vue`） |

### 组件文件命名

| 命名 | 场景 |
|---|---|
| `PascalCase.vue` | 多单词组件（如 `NavBar.vue`） |
| `i-icon/index.vue` | 短横线包裹的目录（kebab-case） |
| 单文件直接放 `index.vue` | 一个目录只放一个组件时 |

## 四、TypeScript 关键配置

```json
// tsconfig.json
{
  "compilerOptions": {
    "target": "ESNext",
    "lib": ["ESNext", "DOM"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "paths": {
      "@/*": ["./src/*"],
      "@build/*": ["./build/*"]
    },
    "allowJs": true,
    "strict": true,
    "types": ["node", "vite/client"]
  },
  "include": [
    "mock/*.ts",
    "src/**/*.ts",
    "src/**/*.tsx",
    "src/**/*.vue",
    "typings/*.d.ts",
    "vite.config.ts"
  ]
}
```

要点：
- **`moduleResolution: "bundler"`**：Vite 项目推荐，对 package.json `exports` 字段支持好。
- **路径别名**：内置 `@` 指向 src，`@build` 指向 build。
- **`strict: true`**：开启严格模式。
- **`allowJs: true`**：允许 JS 文件与 TS 共存。
- **`types: ["node", "vite/client"]`**：声明 `import.meta.env` 等 Vite 内置类型。

## 七、提交规范（Commitlint）

```js
// commitlint.config.js
{
  extends: ['@commitlint/config-conventional'],
  rules: {
    'header-max-length': [2, 'always', 108],
    'type-enum': [2, 'always', [
      'feat', 'fix', 'perf', 'style', 'docs', 'test',
      'refactor', 'build', 'ci', 'chore', 'revert',
      'wip', 'workflow', 'types', 'release',
    ]],
  }
}
```

格式：`<type>(<scope>): <subject>`

支持的 type 列表（15 种）：feat / fix / perf / style / docs / test / refactor / build / ci / chore / revert / wip / workflow / types / release。

## 八、环境变量约定

```bash
# .env.development
VITE_BASE_API = '/dev-api'              # 本地 mock 路径
VITE_ENABLE_ERUDA = "true"               # 启用 eruda
VITE_PUBLIC_PATH = /

# .env.production
VITE_BASE_API = "/"
VITE_PUBLIC_PATH = "/"
VITE_CDN_DEPS = "false"                 # 是否启用 CDN 加载
```

约定：所有 Vite 环境变量必须以 `VITE_` 前缀开头才能在客户端访问。

## 九、与传统 SPA 项目的差异

1. **CSS 入口分离**：全局样式、Less 变量、Tailwind 入口各一文件，按需在 `main.ts` 引入。
2. **SVG 目录与组件目录分离**：`src/icons/svg/` 是源数据，`src/components/svg-icon/` 是读取封装。
3. **`typings/` 单独目录**：放置所有 `.d.ts`，包括 Vite/Router 扩展类型。
4. **无 `router/` 业务子目录**：路由表全平铺在 `routes.ts`；超过时建议拆分为 `modules/`。
6. **`mock/` 在 src 外**：历史 mock 文件保留，新版通过 `vite-plugin-mock-dev-server` + `src/api/mock/` 组合实现。
