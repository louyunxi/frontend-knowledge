> ⚠️ 本知识仅适用于 **uni-app 自定义组件 / uni-app H5 端** 场景。
> 微信小程序/App 没有浏览器跨域限制，**不能**直接复用此方案。

# uni-app 跨域问题解决方案

## 背景

uni-app 在 H5 端本质上仍是浏览器应用，受到浏览器同源策略限制。
开发阶段直接请求 `https://api.example.com` 等非本地域名，会触发 CORS 报错。

## 方案一：开发代理（推荐）

在项目根目录 `manifest.json` 的 `h5.devServer` 中配置代理：

```json
{
  "h5": {
    "devServer": {
      "port": 8080,
      "proxy": {
        "/api": {
          "target": "https://api.example.com",
          "changeOrigin": true,
          "secure": false,
          "pathRewrite": {
            "^/api": ""
          }
        }
      }
    }
  }
}
```

请求代码：

```js
uni.request({
  url: '/api/user/info',
  // 实际被代理转发到 https://api.example.com/user/info
})
```

## 方案二：服务端允许 CORS

在目标接口服务端响应头添加：

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

## 方案三：JSONP（仅 GET）

适合不支持 CORS 的旧后端：

```js
uni.request({
  url: 'https://api.example.com/data?callback=cb',
  dataType: 'jsonp',
  success: (res) => {
    // res.data 为 callback 包裹后的对象
  }
})
```

> 仅 H5 端支持 jsonp，小程序 / App 端需改为服务端 CORS。

## 方案四：Nginx 反代（生产）

部署阶段统一在 Nginx 反向代理，前端无感知：

```nginx
location /api/ {
  proxy_pass https://api.example.com/;
  proxy_set_header Host $host;
}
```

## 实践提示

1. H5 调试时优先用 devServer 代理，避免污染生产配置。
2. 微信小程序 / App 端不存在浏览器跨域，调用 `uni.request` 直连即可。
3. 自定义 header 在小程序端需在「微信公众平台 → 开发设置 → 服务器域名」配置白名单。
4. 携带 Cookie 的接口必须服务端显式 `Access-Control-Allow-Credentials: true`，且 Origin 不能为 `*`。
