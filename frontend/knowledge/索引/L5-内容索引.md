# L5 内容索引

> ⚠️ **当前状态：占位 / 规划中**。
> L5 内容索引（基于知识正文 body 的全文检索索引）当前**尚未落盘**。
> 本文件保留为索引体系完整性的占位说明，实际内容待实施。

正文片段索引，从每个知识文件正文中提取关键段落、代码片段标题、章节标题，
用于在 L1-L4 未命中时兜底召回。

---

## 索引结构

```markdown
| 知识 ID | 章节标题 | 关键片段 | 命中关键词 | 引用次数 |
|---------|---------|---------|-----------|---------|
| {knowledge_id} | {section_title} | {snippet} | {hit_keywords} | {ref_count} |
```

字段说明：

- **knowledge ID**：与 `L1-精确索引.md` 中 `knowledge_id` 完全一致
- **章节标题**：正文中 `##` 或 `###` 章节的标题
- **关键片段**：200 字以内的关键段落摘要，去除代码块和多余 Markdown 符号
- **命中关键词**：该片段在历史召回中命中的关键词集合
- **引用次数**：被 `/frontend` 主命令（需求描述分支或页面路径分支）实际召回过的次数

---

## 与 L1-L4 的关系

```
召回优先级（高 → 低）：
├── L1 精确索引       文件名 / 标题直接命中
├── L2 关键词索引     关键词、同义词命中
├── L3 标签索引       技术栈 / 功能 / 场景标签命中
├── L4 场景索引       场景描述、用户意图命中
└── L5 内容索引       正文片段兜底，仅在前 4 层均未命中时使用
```

L5 是兜底层，召回时应返回**较低权重**的结果（参考 `召回优化指南.md`
中 `calculateScore` 的权重分配），避免在 L1-L4 已覆盖时产生噪声。

---

## 启用条件

L5 内容索引的正式启用必须满足以下前置条件：

- [ ] L1-L4 索引经过至少一轮 `verification/index-sync-checklist.md` 校验
- [ ] `knowledge/` 目录下有 ≥ 30 条知识（少于该数量时 L5 召回性价比极低）
- [ ] 检索引擎支持全文检索（如 SQLite FTS5、Meilisearch 等）
- [ ] 有明确的"命中片段"标注协议（避免把整段正文无差别索引）
- [ ] 检索时附带回链到完整文件路径，便于二次确认

未满足以上条件时，建议继续依赖 L1-L4 完成召回，不要仓促启用 L5。

## 实施计划（占位）

### Phase 1：索引骨架

- 创建 `L5-内容索引.md` 文件（本文件已建立骨架）
- 定义字段：knowledge_id / 章节标题 / 关键片段 / 命中关键词 / 引用次数
- 与 L1-L4 通过 `knowledge_id` 关联

### Phase 2：抽取脚本

- 编写脚本扫盘 `knowledge/<域>/*.md`，抽取 `##` 和 `###` 章节
- 过滤代码块、去除 Markdown 符号，保留 200 字以内摘要
- 自动同步到 L5 索引

### Phase 3：兜底召回

- 在 `recall()` 函数中，将 L5 检索结果权重设为 `0.2 * score`
- 仅在前 4 层均无命中时返回 L5 结果
- 每次命中时记录到 `命中关键词` 和 `引用次数` 字段

---

## 自检要点

- L5 文件中**不得**保存知识正文原文，仅保存摘要和元数据
- L5 中每条记录的 `knowledge_id` 必须能在 `L1-精确索引.md` 中找到
- L5 不得引入 L2 之外的新关键词，避免污染关键词真相源
- L5 抽取脚本不得读取 `.env*`、密钥、Token、Authorization Header 等敏感文件
  （详见 `distill.md` § 安全读取与脱敏）
