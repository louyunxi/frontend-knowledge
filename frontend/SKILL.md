# Frontend Knowledge Skill

前端技术经验知识库、页面方案分析和蒸馏系统。管理、搜索、复用和蒸馏前端项目经验，并把页面事实与跨域知识编排成可执行方案。

> ⚠️ **维护策略（必读）**
>
> 本目录 `frontend/` 是 Skill 的**唯一真相源**（Git tracked），对外推送、团队共享、Skill 发布都以它为准。
>
> IDE 加载目录 `.trae/skills/frontend/`（或 `.claude/skills/frontend/` 等）由 `install.ps1` 创建为 **Windows 目录联接（Junction）**，本质是指向 `frontend/` 的符号链接。物理上**只有一份文件**——任何路径改了文件，另一处立即看到，**不再需要 sync**，也**永远不会 drift**。
>
> - ✅ 蒸馏、修改、新增 → 只动 `frontend/`
> - ✅ 提交：先在 `frontend/` 内 `git add/commit/push`
> - ✅ 给其他 IDE 装一份：`.\install.ps1 -Tool trae -Scope project -ProjectPath .`
> - ❌ 严禁对 `.trae/skills/frontend/` 做 `Copy-Item` / 真复制——会让两份再次分歧

>
> 卸载：`.\install.ps1 -Tool trae -Scope project -ProjectPath . -Uninstall`

## 命令系统

### /frontend - 主命令（自动查询知识库并编排提示词）

当前 skill 的**唯一主命令**，一个命令两种用法：

- `/frontend <需求描述>` — 自动查询知识库，召回匹配的知识点并合理排版为一段提示词，直接带大模型去实现需求或优化页面排版
- `/frontend <页面路径>` — 分析页面功能，匹配需要用到的知识库条目，把知识编排成自包含的改造提示词，带大模型去改造页面

该命令同时承担原 `/frontend:analyze`（页面分析+方案编排）和 `/frontend:knowledge`（关键词搜索+知识匹配）的全部能力。

**默认 auto-execute**：输出 Agent 实施提示词后**立即进入代码改造**，不需要用户手动确认。需要回归"先展示再动手"的旧式行为时，加 `--confirm`；只想预览不动手，加 `--dry-run`；想安静跑，加 `--quiet`。开关可叠加。

**危险命令强制拦截**：不论哪种模式，下列动作在执行前必须单独向用户确认一次（装依赖、跑构建/部署、git push、破坏性操作、改全局配置、CI/CD 改动、提交到 main/master、--force 之类的绕过校验开关）。详细规则见 `commands/frontend.md` 的"执行模式"与"危险命令拦截"章节。

```
使用场景：
├── 想实现某个功能并直接拿到可执行提示词
├── 想改造某个页面的布局、动效、主题并交给大模型
├── 遇到某个技术问题并希望一次性得到方案 + 提示词
└── 任何需要"召唤知识库 → 编排提示词 → 自动落地"的开发任务

触发方式：
/frontend <需求描述>                   # 走"需求描述分支"，默认 auto-execute
/frontend <页面路径>                   # 走"页面路径分支"，默认 auto-execute
/frontend <需求描述> --confirm         # 生成后暂停，等确认再动手
/frontend <页面路径> --dry-run         # 只输出分析 + prompt，不动文件
/frontend <需求描述> --quiet           # 安静模式：压缩中间输出

示例：
/frontend 实现一个带入场动画的筛选表格
/frontend 优化卡片列表的过渡动画
/frontend 给登录页加上暗色模式
/frontend src/pages/ParcelManagement/index.tsx
/frontend src/pages/CustomerList/index.tsx
```

分支识别规则：

- 输入是已存在的本地文件/目录路径 → 走"页面路径分支"
- 输入是自然语言描述、关键词、技术名词或需求场景 → 走"需求描述分支"
- 同一输入同时包含路径和需求时，**优先页面路径分支**，把需求作为补充描述

需求描述分支的产出：召回方案列表 + 知识摘要 + Agent 实施提示词。默认 auto-execute，输出 prompt 后立即实施。

页面路径分支的产出：页面分析报告 + Agent 实施提示词。默认 auto-execute，输出 prompt 后立即实施。

完整规则、决策优先级、跨域编排、阶段流程、执行模式、危险命令拦截与禁止行为见 `commands/frontend.md`。页面路径分支输出遵循 `templates/analyze-output.md`，完成前执行 `verification/analyze-checklist.md`。

### /frontend:distill - 知识蒸馏

> ⚠️ **路径硬约束**：所有蒸馏落盘**只能且必须**写入当前 skill 的 `knowledge/` 目录（即 `frontend/knowledge/`）。严禁写入其他 Skill 目录、其他项目目录或 skill 根以外的任何路径。

当需要从代码或项目中提取技术经验、记录最佳实践或踩坑时使用。

```
使用场景：
├── 发现好的代码实现需要复用
├── 解决了一个问题需要记录
├── 总结某个技术的最佳实践
├── 需要把项目经验转化为可复用模式
└── 遇到并解决了技术难题

触发方式：
/frontend:distill [源文件或路径] --type [类型] --domain [域] [--platform 平台]

示例：
/frontend:distill src/components/Modal.tsx --type pattern --domain 动效
/frontend:distill --type best --domain 功能 --name "虚拟列表最佳实践"
/frontend:distill --type pitfall --domain 动效 --name "动画性能问题"
/frontend:distill src/pages/Orders --type page-layout --domain 布局 --platform web --name "订单筛选表格"
/frontend:distill src/pages/CustomerList --type page-layout --domain 布局 --platform responsive --name "响应式客户列表与详情"
```

### /frontend:list - 知识列表

当需要了解知识库中有哪些可用的技术经验时使用。

```
使用场景：
├── 不知道有哪些可用的技术经验
├── 想了解某个域的具体内容
├── 需要快速找到相关的模式
└── 作为开发的参考索引

触发方式：
/frontend:list [选项]

示例：
/frontend:list                      # 列出所有域
/frontend:list --domain 动效       # 列出动效域
/frontend:list --all               # 列出所有知识
/frontend:list --stats             # 显示统计信息
```

## 自动触发模式（Auto-Trigger）

本 skill **默认开启自动触发**。当用户输入符合下列场景时，**无需显式调用 `/frontend`** 也会激活本 skill，自动匹配知识库、输出 Agent 实施提示词、**并按 auto-execute 立即进入代码改造**。危险命令（装依赖、push、删除等）照常二次确认。输出格式与显式 `/frontend` 命令**完全一致**。

> 💡 如果不希望自动触发后立即动手改造，可在 Trae 偏好中关闭自动触发，或临时让用户用 `--confirm` / `--dry-run` 显式调用 `/frontend`。

### 触发场景分类

#### 类型 A：前端需求描述（对应 `/frontend` 需求描述分支）

**触发动作词**：实现、添加、搭建、做、做出、来个、写个、改成、调整、优化、重构、修复、设计...

**典型输入**：
- "实现一个带入场动画的筛选表格"
- "做暗色模式切换"
- "调整卡片列表的栅格"
- "添加拖拽排序"
- "组件命名规范怎么定"

**自动行为**：走 `/frontend <需求描述>` 分支。

#### 类型 B：页面/文件路径引用（对应 `/frontend` 页面路径分支）

**触发特征**：输入中包含 `src/`、`pages/`、`components/`、`views/`、`layouts/`、`routes/`、`.tsx`、`.vue`、`.jsx`、`.html` 等路径标识。

**典型输入**：
- "src/pages/ParcelManagement/index.tsx 帮我改造"
- "改造一下 components/Modal.vue"
- "优化 pages/login 这个页面"

**自动行为**：走 `/frontend <页面路径>` 分支。

### 与显式命令的关系

| 调用方式 | 触发来源 | 输出 | 行为 |
|---|---|---|---|
| `/frontend <需求>` | 显式命令 | 需求描述分支完整输出 | 完整 |
| `/frontend <路径>` | 显式命令 | 页面路径分支完整输出 | 完整 |
| 用户输入 + 触发词 | **自动** | 需求描述分支完整输出 | 与 `/frontend <需求>` 等价 |
| 用户输入 + 路径引用 | **自动** | 页面路径分支完整输出 | 与 `/frontend <路径>` 等价 |

**简言之**：自动触发 = "省去用户输入 `/frontend` 的过程"，**输出行为完全等价**。

### 关闭自动触发

如果用户希望只在显式调用时触发：
- 在 Trae 用户偏好中关闭"前端 Skill 自动触发"
- 或在当前项目 `agent.md` 中声明 `skill.frontend.auto-trigger: false`

### 注意事项

- **宁严勿宽**：自动触发的判断必须基于明确的 6 大知识域关键词或路径引用，**避免误激活**（闲聊/任务管理/PPT 等不应触发）
- **不与其他 Skill 冲突**：当用户明确使用其他 Skill（如 PPT、图片生成、PDF、Excel）时，**不触发** `/frontend` 自动触发
- **路径引用必须有效**：自动触发的页面路径分支会读取实际文件，路径不存在时应回退到需求描述分支
- **输出与显式命令一致**：自动触发输出的格式与 `/frontend` 完全一致，方便用户预期和复用
- **6 域关键词与 L2/L3 一致**：新增触发词须同步更新 L2/L3，避免自动触发与显式命令的关键词漂移

## /frontend 主命令详解

`/frontend` 是当前 skill 的**唯一主命令**，整合了原 `/frontend:analyze` 和 `/frontend:knowledge` 的能力。它有两种分支，由输入自动识别。

### 分支识别

```text
输入
    ↓
┌──────────────────────────────────────────────────────┐
│ 判断输入类型                                        │
│ ├── 是已存在的本地文件/目录路径 → 走"页面路径分支" │
│ └── 否则 → 走"需求描述分支"                       │
└──────────────────────────────────────────────────────┘
```

### 分支一：需求描述（`/frontend <需求>`）

#### 召回架构

```text
用户输入: "换页动画"
    ↓
L1 精确匹配 (100%)   → title、filename、精确关键词
    ↓
L2 语义匹配 (90%)    → 关键词改写、同义词、L2 索引
    ↓
L3 扩展匹配 (80%)    → 语义变体、标签匹配、L3 索引
    ↓
L4 组合匹配 (60%)    → 多关键词、跨域、技术栈+功能
    ↓
L5 场景推荐 (40%)    → 场景索引、知识图谱
    ↓
结果合并排序        → Score = 精确×0.4 + 语义×0.3 + 标签×0.2 + 相关×0.1
```

#### 评分与排序

```text
匹配优先级：
1. 精确关键词匹配 → 100%
2. 同义词匹配 → 90%
3. 语义变体匹配 → 80%
4. 语义标签匹配 → 70%
5. 部分匹配 → 50%
6. 跨域匹配 → 组合推荐
```

#### 查询改写

```text
1. 口语化改写        "换页" → "页面过渡"
2. 模糊化改写        "页面切换带动画" → "页面过渡"
3. 技术术语规范化     "vl" → "虚拟列表"
4. 意图补全          "优化列表" → "列表性能优化 + 虚拟列表"
```

#### 输出形态

```text
1. 召回方案列表（人类可读）
   - 匹配度、来源层级、适用场景
   - 核心代码或要点摘要
   - 跨域推荐、关联推荐

2. 知识摘要（提示词素材）
   - 提炼召回到的知识要点
   - 标注每条要点来自哪个知识条目

3. Agent 实施提示词（可直接复制）
   - 自包含、可单独交给大模型执行
   - 目标、技术栈、要点清单、实施顺序、验收标准
```

#### 召回结果格式

```markdown

[代码]

### 相关模式
- [相关模式1] - [关联说明]
- [相关模式2] - [关联说明]
```

### 分支二：页面路径（`/frontend <页面路径>`）

读取页面及项目上下文，跨域检索前端知识，生成可直接交给实现 Agent 的完整页面实施方案。命令默认 auto-execute（输出 prompt 后立即进入实施），需停止实施可加 `--confirm` / `--dry-run`。

完整流程、决策优先级、跨域编排与禁止行为见 `commands/frontend.md`；输出模板见 `templates/analyze-output.md`；完成前执行 `verification/analyze-checklist.md`。

#### 输出形态

```text
1. 页面分析报告（人类可读）
   - 项目约束、页面事实、模块清单
   - 知识召回与裁剪（采用 / 可选 / 排除 / 缺失）
   - 最终页面方案（骨架 + 模块）
   - 风险与证据缺口
```

## /frontend:distill 命令详解

### 命令格式

```
/frontend:distill [源路径] --type [类型] --domain [域] [--platform 平台] [--name 名称]
```

### 参数说明

| 参数 | 必填 | 说明 | 可选值 |
|-----|------|------|--------|
| `源路径` | 条件 | 代码文件、页面入口或目录路径；`page-layout` 时必填 | 文件路径、目录路径 |
| `--type` | 是 | 蒸馏类型 | `pattern`、`best`、`pitfall`、`page-layout` |
| `--domain` | 是 | 知识域；`page-layout` 时必须为 `布局` | `动效`、`布局`、`功能`、`项目规范`、`设计主题`、`技术选型` |
| `--platform` | 条件 | 页面布局目标平台；仅用于且必用于 `page-layout` | `web`、`mobile`、`responsive` |
| `--name` | 否 | 模式名称 | 自定义名称 |

## 常见问题

### Q: 什么时候用 /frontend？

A: 任何时候你需要让大模型按知识库的最佳实践**实现新需求**或**改造已有页面**，都用 `/frontend`：

- `/frontend <需求>` — 例如 `/frontend 实现一个带入场动画的筛选表格`
- `/frontend <页面路径>` — 例如 `/frontend src/pages/ParcelManagement/index.tsx`

它会自动查询知识库、召回匹配的知识点、编排为自包含的提示词带大模型去落地。

### Q: 什么时候用 /frontend:distill？

A: 当你需要**创建**新的知识条目时。例如："发现好的代码要复用"、"总结最佳实践"、"记录踩坑"。

### Q: 两个命令如何配合使用？

A: 先用 `/frontend` 驱动大模型开发，遇到值得固化的经验再用 `/frontend:distill` 蒸馏进知识库，下次 `/frontend` 就能自动召回到。
