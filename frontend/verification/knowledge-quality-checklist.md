# 知识准入门槛清单 (knowledge-quality-checklist)

> **用途**：任何知识文件进入 `knowledge/` 之前必须通过本清单，是"`verification/distill-checklist.md`"的前置关卡。
> **执行时机**：distill 起草前先预审；落盘前再终审一次。

---

## 1. 来源与证据

- [ ] 知识有真实项目代码 / 文档 / 设计规范作为来源
- [ ] `source_scope` 明确写出项目类型、模块、文件路径或文档位置
- [ ] 关键结论附有源文件路径或设计文档引用
- [ ] 推断、推测和已验证事实已显式区分（不得把推测写成事实）
- [ ] 不含 `.env*`、密钥、API Key、Cookie、Authorization Header 等敏感信息
- [ ] 不含完整接口响应、真实用户数据、内部域名或租户 ID

## 2. 内容完整性

- [ ] frontmatter 完整：`title`、`description`、`domain`、`type`、`source_scope`、`observed_platforms`、`confidence`
- [ ] 含核心实现 / 代码片段 / 关键配置
- [ ] 含使用步骤或接入路径
- [ ] 含注意事项 / 边界 / 不适用条件
- [ ] 至少一段"为什么这样做"或权衡说明，避免纯 API 抄录
- [ ] 关联知识已通过相对路径链接

## 3. 命名与归类

- [ ] 文件名遵循 `{域}-{主题}-{修饰}.md`（page-layout 例外：`[页面任务]-[平台].md`）
- [ ] `--domain` 与目标目录一致：`--domain 动效` → `knowledge/动效/`
- [ ] `domain` 与归类目录大小写/中文完全一致
- [ ] `type` 取自 `pattern` / `best` / `pitfall` / `page-layout`
- [ ] 不与现有知识重名（重名必须走合并流程而非直接覆盖）

## 4. 可复用性

- [ ] 该知识在至少一类项目场景下可复用，不局限于单一项目
- [ ] 来源范围与泛化边界在 `source_scope` 与正文显式记录
- [ ] 差异化平台/版本要求已标注
- [ ] 不包含项目特有业务逻辑（如特定租户 ID、内部 SKU 表）

## 5. 召回可用性

- [ ] 关键词覆盖：技术栈名、功能短语、语义变体、口语表达
- [ ] 同义词已加入 L2-关键词索引
- [ ] 标签已加入 L3-标签索引
- [ ] 场景已加入 L4-场景索引（如适用）
- [ ] 至少 3 个不同查询（含同义/口语）自检索命中

## 6. 阻断条件

出现以下任一情况 → 不得落盘到 `knowledge/`：

- 没有任何真实代码 / 文档来源
- 关键结论全部来自推测
- 内容触敏（凭据、密钥、内部隐私）
- 文件名不满足命名规范且未走特殊审批
- `domain` 与目录不一致
- 关键词无法让 `/frontend`（需求描述分支）召回
- 与现有文件同名但未走合并流程
- 内容仅是官方 API 抄录而无项目场景或权衡
